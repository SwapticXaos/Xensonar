# Nodal/Melodic artifact forensics and direct route proposal

2026-10-22; live source based on 18fc033 plus cumulative source integration. Historical user store unavailable: these results prove reproducible mechanisms, not the cause of the historic missing user object.

## Native IndexedDB evidence

`forensics-browser.cjs` runs the actual source functions in disposable Chromium origin `http://nodal-forensics.test`, with native IndexedDB. A native store put receives request success and its transaction is then explicitly aborted. Current `bg` resolves despite the absent record. Actual `B9e` subsequently rejects only on its verification read, but `bu` has already inserted the material into `Ei` and emitted `registered`. Injected QuotaExceededError on native store similarly leaves an advertised ghost. Root Follow membership itself is blocked by the new fence in these two cases. Raw evidence: `before-durability.json`.

The baseline DB opener does not close connections or register versionchange handling. `bg`, `OS`, `Khe`, `em`, `Uhe` wait for request success rather than transaction completion. `KT` silently returns success if IndexedDB is absent. `bu` advertises before persistence. These are proven source issues; unavailable storage, midcommit abort and quota need explicit export errors.

## Current call graph and ownership

`B9e` -> `VR` -> `P9e` offline render -> `I9e` material package -> adapter `$M(Ly(...))` -> `bu` -> `a0e` -> `GS` -> `KT` -> `bg` -> `NS`/`DS`; after fence/readback -> `ri(rootFollowBankMembership)` -> bank normalizer `tg`/`tge` -> localStorage bank. Hydration: `uh` fire-and-forget -> `u0e` -> `em(QT)` -> fresh Blob URLs -> merge current entries over persisted rows -> `GS`.

Nodal project definitions already embed immutable normalized instruments keyed `nodal:<libraryID>@<revision>` in `composer.nodalInstruments`. `nodalFindInstrument` prefers embedded definition then falls back to current matching library revision. `nodalUpdateMelodicInstrument` creates a new revision and substitutes only project references. Export does not persist the project definition in the material package. `L9e` synthetic pattern drops the definition bank; `tge` normalizer would drop it again. Native synthetic events carry lineHz and existing tuning metadata but not a complete owned dependency closure. `__mlNodalRflConfig` deliberately selects material/flowing whenever a Nodal/custom/Entrophon note or pan exists.

Existing direct RFL: `lSe` builds windows through `Jye`, retunes `activeSynthVoices` using `Dye`, dispatches via `cSe`. Existing Nodal direct backend: `__XenNodalLive.createPlayer` -> `prepare`/`pin` immutable instrument -> `noteOn` -> worklet voice; returned voice supports `setFrequency`. Worker `createNodalPreparationCoordinator` computes plans and pitch packets; processing retains fixed slot arrays, staged voice pools and quantum guard. Offline Nodal `nodalScheduleOffline` currently materializes PCM using `__XenNodalDSP.render`.

## Bounded durability fix (approved separately)

Add one transaction helper: attach completion/abort/error before starting request, save request result but resolve only `transaction.complete`, reject native named error on abort, close connection in all outcomes, close on versionchange, report blocked opens. Use for all existing thin DB helpers to avoid false write success and connection leakage. Preserve synchronous `bu` API for unrelated best-effort callers. Add explicit async durable registration for artifact exports: validate/snapshot package, await commit, verify persisted record if needed, then create/reuse URL and publish GS/registered. Failure revokes unpublished URLs and emits structured stage/id/name/code. Guard pending writes against delete/supersession and reject the export if its generation is no longer current. No old blob deletion, no global bank reset, no unrestricted fallback.

## Schema and direct route decision requested

Introduce `melodicSnapshot` schema `xensonar.melodic-snapshot`, version 1, owned by material library record (not editable project or bank metadata). Snapshot fields: canonical selected composer timeline/pattern/boundaries, exact note pitches/ratios and repetition interval (no assumed octave/12EDO), BPM/bars/beats-per-bar, tracks/pans/gain/envelopes, each per-note/track source with immutable definition reference. Store normalized Nodal definitions under semantic content keys; use stable canonical serialization and SHA-256. Preserve exact instrument schema/kernel versions. Capture any sample-dependent source blobs in the durable dependency closure; no object URLs in semantic payload. Optional rendered WAV remains a cache/compatibility payload. Freeze/copy normalized snapshot; project edits cannot mutate it. Cache eviction never deletes the artifact definition.

Add explicit snapshot config identity/hash to `tg` rather than forcing all source types into material/synth enum. Preserve legacy migration path: old material rows continue existing playback; old synth patterns remain accepted. Do not manufacture absent Nodal definitions from an unrelated current preset. Legacy material is playable as existing material, with provenance identifying its narrower saved definition.

RFL preparation resolves material snapshot by identity, validates dependency hashes and constructs per-source plans once, before transport ownership. Reuse existing `Jye` timing/drop/budget logic; dispatch ordinary synth notes through existing `cSe`, Nodal notes through prepared direct player, and sample notes through the existing sample backend. Keep Nodal player instruments pinned for snapshot lifetime. Track panning is handled per output/player, not a reason to force the entire loop through WAV. Retune active Nodal voices from stored exact frequency ratio using current root, preserving attack and age; coalesce pitch preparation on worker and install packets before audio deadlines. Use existing global admission plus dedicated low priority for RFL so Beat/Bass/Material keep priority. Dispose on generation/token changes, no catch-up replay.

Required acceptance: real UI send Nodal/synth/hybrid and inspect output PCM immediately, after hard reload, space changes, source preset edit/delete and project delete; equal semantic hashes across those mutations. Nodal worklet voices and changing frequencies must be observable without full-WAV/granular ownership. Native IDB abort-after-success, quota, reload-before-commit and hydration/delete/reorder races must never publish. Performance measured separately under particles/wave starters, not concurrently with functional browser trials.
